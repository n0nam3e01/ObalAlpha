# Öbal Alpha

Еда из заведений рядом со скидкой. Заберите сегодня в указанное время.

React/Vite → Express/Prisma → PostgreSQL. Только самовывоз, без дополнительного сбора покупателю. Онлайн-оплата и Telegram не подключены. Supabase — предложенный хостинг базы, не уже подключённая авторизация.

## Запуск

Нужна PostgreSQL. Заполните `backend/.env` по `.env.example`: DATABASE_URL, DIRECT_URL и случайный JWT_SECRET.

```powershell
cd backend
npm ci
npm run build
npm run db:migrate
npm start
```

В другом терминале:

```powershell
cd frontend
npm ci
npm run dev -- --host 127.0.0.1
```

Интерфейс: http://127.0.0.1:5173. API: http://127.0.0.1:3000/api/health. Vite проксирует `/api`, frontend `.env` локально не обязателен. При сбое API показывается ошибка, а не подставной каталог.

`npm run seed` с ALLOW_DEMO_SEED=true **удаляет заказы и наборы** и создаёт примеры. Только для одноразовой локальной базы. В production заблокирован. Коды заведений печатаются в терминале. Окна выдачи вечерние, автоматически не переносятся на следующий день.

## Проверки

В backend: `npm test`. Интеграционный тест требует TEST_DATABASE_URL отдельной базы с именем `obal_test` или `obal_test_*` с применёнными миграциями. Создаёт и удаляет только свои записи. Без переменной явно пропускается.

Проверено на настоящей PostgreSQL: регистрация/вход, доступ только к своим заказам, конкурирующие брони последней порции, повторная отмена и выдача, цены без сборов, закрытые окна, отсутствие секретов в публичных ответах. Сборка frontend проходит. Это не проверка production-инфраструктуры.

## Правила MVP

- Бронирование блокирует строку набора до проверки остатков и создания заказа. Цену и комиссию считает сервер.
- Отмена/выдача — условные переходы статуса: повтор не меняет остатки или экономию второй раз.
- Окна — время Астаны UTC+5, reserved_until хранится как UTC timestamp. Просроченная бронь становится NO_SHOW и не возвращает еду в каталог.
- Набор с действующими/выданными заказами нельзя переоценить или изменить: создайте новый.
- Отчёт считает выданные заказы и сохранённую комиссию, не фактическое поступление денег.
- Старые поля доставки оставлены ради истории. Новые заказы только PICKUP, service_fee=delivery_fee=0.

## Хостинг

| Часть | Сервис | Настройки |
| --- | --- | --- |
| Frontend | Vercel | Root Directory `frontend`, Vite, build `npm run build`, output `dist` |
| Backend | Render Web Service | Root `backend`, build `npm ci --include=dev && npm run build`, start `npm run db:migrate && npm start`, health `/api/health` |
| База | Supabase PostgreSQL | Session pooler 5432 для DATABASE_URL и DIRECT_URL; direct при доступном IPv6 |

Backend: NODE_ENV=production, HOST=0.0.0.0, TRUST_PROXY_HOPS=1 (только за одним доверенным прокси), CORS_ORIGIN=https://obal-alpha.vercel.app, DEMO_MODE=false. DATABASE_URL, DIRECT_URL, JWT_SECRET — только серверные секреты. Для нескольких реплик миграции переносим из start в один pre-deploy job.

Frontend: VITE_API_URL=https://адрес-api без `/api`, затем новая сборка. Переменная встраивается при сборке. Секреты в VITE_* запрещены.

Для пилота с реальными заказами нужен постоянно работающий API: бесплатный Render засыпает, процессный cron во сне не работает. Проверки срока в запросах бронирования/выдачи действуют независимо. Пока одна реплика: rate limit хранится в памяти. При росте нужны общие лимиты и отдельный планировщик.

При работе с Supabase только через Prisma отключите Data API: таблицы public без RLS иначе могут открыться в обход Express. Демотокены seed в production не использовать. Токены заведений, ранее попавшие в публичные ответы старого API, нужно перевыпустить перед запуском.

Источники: [Vite/Vercel](https://vercel.com/docs/frameworks/frontend/vite), [Express/Render](https://render.com/docs/deploy-node-express-app), [Supabase/Prisma](https://supabase.com/docs/guides/database/prisma), [бесплатный Render](https://render.com/docs/free).
