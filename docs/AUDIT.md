# Аудит Öbal Alpha — 4 октября 2026

Проверено: весь код backend и frontend, миграции, конфигурация деплоя. Приложение запущено локально на PostgreSQL 16, прогнаны unit- и интеграционные тесты, сценарии проверены в Chromium (Playwright) на ширине 390 и 1280 px.

Обозначения: [исправлено] — сделано в этой ветке; [открыто] — требует решения или отдельной работы.

## Итог

Ядро заказа сделано аккуратно: блокировка строки набора при брони, ключ идемпотентности, условные переходы статусов, цены считает сервер, время Астаны в одном модуле, интеграционный тест на настоящей PostgreSQL. Слабые места — не в логике заказа, а вокруг неё:

1. Две трети фронтенда — мёртвый код, живое приложение было одним файлом на 450 строк с JSX в одну строку.
2. Безопасность сессий: долгоживущие JWT в localStorage без отзыва, коды и токены заведений хранятся в базе открытым текстом.
3. Инфраструктура пилотная: бесплатный Render засыпает, лимиты и cron в памяти одного процесса, нет CI, мониторинга и резервного копирования.
4. Нет продуктовой обратной связи: восстановления пароля, подтверждения контакта, уведомлений о брони, аналитики.

Поднята локально: PostgreSQL 16, роль `obal`, базы `obal_local` (демо-данные seed) и `obal_test` (интеграционные тесты). Все 6 миграций применены, `prisma migrate diff` расхождений не показывает.

| Проблема | Статус |
| --- | --- |
| Инварианты держались только в коде API: цена ниже обычной, остаток 0…qty_total, звёзды 1–5, комиссия 0–100, формат времени `HH:MM`, неотрицательные суммы. Скрипт `venue:add`, админка или будущий маршрут могли их нарушить. | [исправлено] миграция `20261004120000_check_constraints`: 11 CHECK-ограничений. Добавлены как `NOT VALID`, чтобы деплой не упал на старых строках. После проверки production выполните `prisma/sql/validate_constraints.sql`. ## UI/UX — критика по методике design-critique

### Первое впечатление (до правок)

На телефоне первый экран целиком занимал герой высотой 440 px. Первая карточка начиналась ниже сгиба и перекрывалась нижней навигацией. Код получения — главное, что покупатель показывает на кассе — был набран шрифтом 16 px под кнопкой «Отменить».

### Удобство использования

| Находка | Серьёзность | Что сделано |
| --- | --- | --- |
| Код получения 16 px, без рамки, ниже кнопки отмены | критично | Экран заказа стал билетом: код 40–52 px моноширинным шрифтом, статус «Можно забирать / Скоро выдача», время, адрес, кнопка «Маршрут». Отмена — красной текстовой кнопкой внизу |
| После брони — молчаливый переход на «Заказы» | серьёзно | Новый заказ подсвечен и помечен «Заказ оформлен» |
| Билет не обновлялся после выдачи на кассе | серьёзно | Опрос каждые 20 секунд и при возврате на вкладку, пока есть активные брони |
| API оценок есть, интерфейса нет — рейтинги заведений всегда 0 | серьёзно | В истории у полученных заказов 5 звёзд, оценка сохраняется сразу |
| Первая карточка ниже сгиба | серьёзно | Герой сжат до заголовка и счётчиков «N наборов сегодня · до −X%» |
| Нет сортировки, хотя API её поддерживает | средне | «Выгоднее / Скоро закончится / Дешевле / Рядом» (геолокация браузера) |
| Пустые категории в фильтре | средне | Показываются только категории с наборами, с количеством |
| «Назад» в карточке всегда вёл на главную, сбрасывая поиск | средне | Возврат по истории; запрос поиска хранится в URL |
| Битая ссылка на фото показывала иконку и alt-текст | средне | Брендированная заглушка с инициалами заведения |
| Состав набора выводился одной строкой без переносов | средне | Список; для сюрприза — пояснение про аллергены |
| Дата «04.10.2026» вместо «Сегодня»; не видно, идёт ли выдача сейчас | средне | «Выдача идёт до 23:00» зелёным или «Сегодня 20:00–23:00» |
| Недоступный набор — серая кнопка без причины | средне | Причина: «Все наборы разобрали» / «Время выдачи прошло» и ссылка на другие наборы |
| Вход: тема приложения стояла над формой входа | средне | Форма первой, тема и ссылки ниже; кнопка показа пароля; `type=tel` для телефона; подсказка про 8 символов; при «аккаунт уже есть» переключает на вход |
| Возврат после входа работал только для `/box/*` | низко | Работает для любого внутреннего пути, включая «Заказы» |
| Новичку не объяснено, как работает сервис | средне | Блок «Как это работает» из трёх шагов на главной |
| Кабинет: на телефоне выдача заказов была в самом низу, под таблицей наборов | критично для кассы | Выдача первой; поле кода крупное, цифровая клавиатура, фокус возвращается после подтверждения |
| Кабинет: новые брони появлялись только по кнопке | серьёзно | Автообновление каждые 30 секунд |
| Кабинет: «Выдача подтверждена» без деталей | средне | «Выдано: <набор> — <имя>. Примите оплату.» |
| Кабинет: в списке ожидающих не было времени и телефона | средне | Окно выдачи и ссылка `tel:` |
| Кабинет: не объяснено, почему набор не виден покупателям | средне | Баннер о модерации, после публикации — «Набор отправлен на проверку» |
| Форма набора: скидка не видна до сохранения, ошибка «цена выше обычной» только с сервера | низко | Скидка считается на лету, проверка до отправки, окно выдачи по умолчанию из настроек заведения |

### Визуальная иерархия

- Сначала взгляд падает на поиск и героя, затем на категории и первую карточку. После правок карточка видна на первом экране 390×844.
- Цена — самый контрастный текст карточки, это правильно. Скидка и остаток вынесены на фото. «Последние 2» выделены тёмной плашкой.

### Доступность

- Контраст: `--muted #75615f` на `--canvas #fbf5f3` ≈ 5.4:1, проходит AA. Белый на `--accent #b25252` ≈ 5.0:1, проходит. Зелёный статус на `--green-soft` ≈ 5.2:1. Логотип `#ca6666` на светлом — 3.5:1, допустимо только для крупного текста.
- Касание: кнопки звёзд, показа пароля, отмены — 44×44 px.
- Код получения озвучивается по цифрам (`aria-label`), статусы объявляются через `role="status"`.
- Скелетоны вместо текста «Загружаем…»; анимации отключаются при `prefers-reduced-motion`.
- [исправлено] Фиксированный шум-оверлей на весь экран с `mix-blend-mode` перерисовывался при каждом кадре прокрутки на слабых телефонах — смешивание убрано.
- [открыто] `window.confirm` для отмены брони и снятия набора — системный диалог на английском в части браузеров. Заменить на собственный диалог с `<dialog>`.

### Что хорошо

- Палитра и типографика единые, тёмная тема работает без мигания (тема ставится до загрузки React).
- Честная подача цены: «оплата на месте, сборов нет» на каждом шаге.
- Есть skip-link, фокус-обводка, safe-area для iPhone.

## Продукт и запуск

| Пробел | Почему важно |
| --- | --- |
| Нет уведомлений о брони и выдаче (push, SMS, Telegram) | заведение узнаёт о брони только из открытого кабинета, покупатель — только из приложения |

## Приоритеты

1. Удалить мёртвый код фронтенда и `lib/telegram.js` (одна команда, см. ниже).
2. CI: тесты backend с postgres + сборка frontend на каждый PR.
3. Восстановление пароля, подтверждение контакта, удаление аккаунта — до публичного запуска.
4. Хэшировать коды и токены заведений, не отдавать `access_code` клиенту; укоротить клиентский JWT.
5. Платный Render (без сна) или другой постоянный хостинг, Sentry, бэкапы Supabase с проверкой восстановления.
6. Уведомления заведению о новой брони.
7. Выполнить `prisma/sql/validate_constraints.sql` на production после проверки данных.
