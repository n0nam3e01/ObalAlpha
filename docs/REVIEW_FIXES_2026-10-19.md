## Важные решения

- После отмены заведением набор получает EXPIRED: возвращённая порция не продаётся повторно. Сотрудник видит, что остальные брони сохраняются, и должен отдельно обработать каждую невозможную выдачу.
- PAID не отменяется через новый маршрут: без процесса возврата такое действие было бы некорректно. В билете нет предложения повторно оплатить PAID заказ.
- Старым заказам не присваивается выдуманное время выдачи. Выдачи без `picked_up_at` не включаются в новые временные агрегаты. Их историческая сверка остаётся отдельной задачей C6/C7.
- Единый порядок блокировок покупатель → набор → заказ сохраняет корректность при одновременных брони, отмене и выдаче.
- Ревью выявило гонку: после действия refresh мог переиспользовать старый опрос. Добавлен режим `fresh`, который дожидается старого запроса и делает новый. Регрессионный тест сначала воспроизвёл ошибку, затем прошёл.
- Опрос и уведомление в открытой вкладке не считаются внешним напоминанием о получении (B4).
- Транзитивная `source-map-js` обновлена в допустимом диапазоне после подтверждённого npm advisory. Frontend audit после обновления: 0 уязвимостей.

## Как проверить

Итоговый локальный прогон после исправления гонки обновления: **backend 28/28, frontend 6/6, браузерный сценарий 1/1 (43,7 с), пропусков и ошибок нет**. Все 7 миграций применены на отдельной PostgreSQL 16.14 с UTF-8; повторный migrate deploy подтвердил отсутствие ожидающих миграций. Production-сборка frontend прошла: JS 421,62 kB / gzip 142,49 kB, CSS 39,67 kB / gzip 8,61 kB. `git diff --check` прошёл. Это размеры сборки, а не измерение реальных Web Vitals.

1. Поднять отдельную PostgreSQL с UTF-8 базой `obal_test` или `obal_test_<suffix>`; не использовать production URL. Для браузерных тестов допускается только loopback-хост.
2. В backend установить зависимости и задать `DATABASE_URL`, `DIRECT_URL`, `TEST_DATABASE_URL` на эту базу. Выполнить `npm run build`, `npm run db:migrate`, `npm test`.
3. В frontend выполнить `npm ci`, `npm test`, `npm run build`.
4. Установить Chromium командой `npx playwright install chromium` и выполнить `npm run test:e2e` с тем же `TEST_DATABASE_URL`. На Windows можно задать `PLAYWRIGHT_CHANNEL=msedge` для установленного Edge. Playwright сам запускает тестовые API/Vite на 3301/5175 и удаляет только созданные им записи.

В CI отсутствие TEST_DATABASE_URL вызывает ошибку, а не незаметный пропуск интеграционного теста. В обычном локальном запуске без переменной интеграционный тест по-прежнему пропускается явно.

Для публикации backend требуется применить миграцию `20261019120000_order_lifecycle` до запуска обновлённого API. Production миграция в рамках этой работы не выполнялась.
